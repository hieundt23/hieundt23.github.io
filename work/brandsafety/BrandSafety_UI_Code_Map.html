Validation & side-effect (trong createAudience)

1) Trùng title (cùng user, chưa xóa) → chặn · 2) keywords null → chặn · 3) kwsMinMatch > số keyword → chặn · 4) Sinh audience_token = hash(title:userId:timestamp) → gắn vào JS tracking · 5) Lưu vào brandsafety_service_audience
Lưu ý / điểm cần check lại:
• [Đã giải đáp] 3 ô đếm xanh/cam/đỏ cạnh "Keywords": là phân loại type của keyword qua POST /api/v1/check-kw-type → 1 = stopword (từ dừng), 2 = cụm từ nhiều chữ, 3 = từ đơn. 3 ô đếm số keyword theo 3 loại này (có backend hỗ trợ, không chỉ FE).
• "Min match" là khái niệm cốt lõi: quyết định phải khớp bao nhiêu kw mới flag — giải thích các audience tên "test min match keywords" trong danh sách.
• Tạo/sửa audience → collection dùng nó bị đánh dấu chạy lại ở media-processing (ReprocessCollection).

Lưu ý:
• "Trạng thái: Có thông tin" = keyword đã được tính. Nếu Check keyword chưa có trong bảng → code gọi insertKeyword() để queue cho job tính sau (trạng thái "chưa có thông tin") → mô hình tính nền, không realtime.
• Số "loại trừ" (excluded) giúp khách hình dung cái giá về reach khi chặn 1 keyword.
• Số liệu keyword do bên NEWS (bs-news-processor) tính → điểm chạm media ↔ news.
